# Entity Alive — project notes

An alien, music-feeling desktop being. Its body is the original entity's ray-marched liquid-metal shader; its inner life is built from the building blocks every hearing creature shares (self-tuned critical ear, excitable tissue held near criticality, brainstem startle, rhythm resonance, expectation, dopamine, affect). Research and experiments live in `lab/`. Electron + plain ES modules, no bundler.

## Layout

- Setup (`Setup.cmd`, `Launch.cmd`, `setup/`): `bootstrap.ps1` fetches a checksum-verified private Node runtime into `.runtime`, then `server.mjs` serves the wizard (`wizard.html/css/js`, token-guarded localhost page shown in an Edge app window) and exits when it closes. `core.mjs` installs (checks: Windows x64, disk, Windows build for per-app capture; `npm ci --ignore-scripts`; Electron's own install; native capture check; icon from `icon.mjs`; shortcuts via WScript.Shell; fingerprinted `.setup/ready.json`) and launches (waits for `BEING_READY_FILE`). `--install-only` installs headless (`--no-shortcuts` leaves shortcuts untouched); `BEING_SHORTCUTS_DIR` redirects all shortcuts into one folder (tests). In the app, `being/settings.html` is the first-run card and Settings (source, size, performance auto/sharp/light, one "understand the music" switch for the four local models, on top, start with Windows via a Startup shortcut; the pixelate / colour levels / dither look lives in the dashboard's Look group).
- Linux (`setup.sh`, `launch.sh`): `setup.sh` checks Node 20+ and `pactl`/`parec`, runs `npm ci --ignore-scripts`, Electron's own install, writes the icon (also into the user's hicolor theme as `being-entity`), `being.desktop` in `~/.local/share/applications` and on the desktop (trusted via `gio`; `--no-desktop` skips it; `StartupWMClass=entity-alive`, the package name, so the dock groups it; a 'dashboard' action passes `--dashboard`, honoured by a running instance too) (`--autostart` adds `~/.config/autostart/being.desktop`, `--uninstall` removes them all) and `.setup/ready.json`. Capture is `native/capture-linux.cjs` (no addon): apps are identified by name, not pid (Flatpak Spotify's stream carries no pid): sink inputs (`pactl -f json`) plus open MPRIS players (`playerctl`), so a paused Spotify is listed; one app is `parec --monitor-stream` on its stream, followed as it opens new ones and waited for while silent; `setOwn` keeps its own voice out, all system audio is `parec -d @DEFAULT_MONITOR@`; both arrive as `pcm` (`startSystemCapture`), since Chromium has no loopback audio on Linux. Track titles come from MPRIS via `playerctl`. On X11, `screen.getCursorScreenPoint()` goes stale while the pet ignores mouse events (no forwarding on Linux), so `main.cjs` `cursorPoint()` reads the pointer from the X server (`native/x11-pointer.cjs`, a tiny QueryPointer client over the X socket) for hover and drag. Native Wayland sessions are not handled. Settings' startup toggle writes the autostart entry.
- `main.cjs`: Electron shell. The default page is the being (`being/index.html`, preload `being/preload.cjs`). `ENTITY_PAGE=fly` loads the earlier fly-connectome + MilkDrop experiment (`renderer/`, `brain/`). Audio comes from Windows per-app loopback (`native/`, checksum-verified addon) or all system audio. The right-click menu is built here. Every window is sandboxed: `being/preload.cjs` asks main for the tuning schema (`page-schema`) and whether the local folder exists (`has-local`, sendSync; it looks on disk first, since a sendSync nobody answers blocks the page, which matters for the unsandboxed `scratch/` harnesses). Settings, song memories, their index and the rng record are written with `being/atomic.cjs` (`writeFileAtomic`: a temp file renamed over the target).
- `main.cjs`: the being runs as a desktop pet by default: frameless, transparent, always on top, click-through except over the creature (`hit`), draggable (`drag`/`drag-end`), no UI (`?ui=0` adds `body.pet`, which hides the dials, captions and panels). Settings live in `<userData>/being-settings.json` (`pet`, `size`, position, `top`); `ENTITY_WINDOW=1` or "Show in a window" uses an ordinary window with the dials. A tray icon and the right-click menu hold the actions. A second launch opens the dashboard of the first. `ENTITY_SHOT=<dir>` (lab) saves screenshots and quits.
- `being/dashboard.html` (+ `dashboard-preload.cjs`, sandboxed): the developer dashboard. Panels include Hearing (the genre / mood model: genres, styles, moods, instruments, themes, character, genre history, embedding; 'Steer the being' toggle), the skin genome, voice, layers with auto/on/off, and per-pass GPU time; panel and rail state persist; Freeze (space) pauses updates. While it is open the page sends a full snapshot (~8/s: ear, tissue, mind, rhythm and timing grids, skin genome and stains, layers, sleep, pressure, beads, materials, memory, GPU timer queries, the unrolled skin every 2.5 s) over `dev-snap`, and the dashboard sends commands over `dev-cmd` (tuning, persisted in localStorage `being-tune`; stains, light, metal; forced material, skin family mix, maturity, maximalism, sleep, per-layer on/off; raw uniforms; actions) and window/audio settings over `dash-app`. Overrides live in `DEV` in the page; presets are stored in the dashboard. Panel modules live in `being/dash/` (`organism-panel.mjs`, the Organism panel; `organism-proxy.mjs`, a remote organism built from `snap.organism` so the lab's views in `lab/prototypes/organism/` run unchanged). The panel's "Let it move ON" switch sets dash-app `organism` `{ drive }`. Each emergent area is named by what it is measured to do (`lab/prototypes/organism/roles.mjs`, pure: over ~20 s, its input mix by sender, output mix by receiver, and its firing around impacts (`live.spikeAge`) and against the shown beat (`live.beatPhase`): listener, body-sense area, hit detector, predictor, beat-keeper, need-driven area, motor driver, integrator); Diagram lays the groups out as a flow, senses → listeners → integrators → feeling core → muscles and skin.
- `being/index.html`: the original entity page (copied from the old app's `blob.html`) with the being patched in. Its body organs are spherical-harmonic cymatics (`uSH`), a quaternion-Julia nucleus (`uJc`, `uNuc`), a living Lenia skin that carves the metal as height (`uSkin`), and the tissue's faint flashes (`uTissue`, `uTissueC`), and a feedback aura (`renderBeing`, `FB`). `beingBody()` and `beingEvents()` drive them from the mind. Its self-contained parts live in `being/page/`, each a factory given the shared objects (later-declared or reassigned names as getters): `shaders.mjs` (the body fragment shader as `bodyFragment({ EXT, ... })`, built after the local folder is imported; aura, composite and unwrap shaders), `gpu-timing.mjs`, `input.mjs` (PCM, stereo, the worklet), `hud.mjs`, `calibration.mjs`, `sky-ring.mjs`, `immersive.mjs`, `glitch.mjs`, `jumps.mjs`. The core frame loop stays in the page. `scratch/fingerprint.cjs` (compiled shaders and uniform names and types) checks that such a move leaves what ON draws unchanged.
- `being/physics.mjs` (pure): the body's mass, viscoelastic membrane, inner fluid slosh and five l = 2 surface modes, pushed by window drags, pointer whips, sub-bass and hits; its strain and jolt go to the mind as proprioception (`senses.proprio`).
- `being/fft.mjs` (pure): the one radix-2 FFT (cached tables, a real-input path) used by `analysis.mjs`, `ml/mel.mjs`, `ml/vggish-mel.mjs` and `ml/beat-core.mjs`; `tests/fft.test.mjs` checks it against a direct transform.
- `tools/serve.mjs`: a static server for viewing the page and the lab pages from a browser. Local only (`127.0.0.1`) unless `HOST=` is set; it serves only an allowlist (`being/` but never `being/local/`, `lab/prototypes/`, three's `build/` and `examples/jsm/`, onnxruntime-web's `dist/`), tested in `tests/serve.test.mjs`.
- `being/input-gain.mjs` (pure): the input trim. Per-app loopback arrives near -40 dBFS, where the analyzer's absolute floors miss most drum hits and every song reads as quiet; `pushIn` in the page passes every chunk through it (instant up, ~60 s down, at most 6 dB/s, x1..x32, still in silence), so the stream sits at a normal level before the analyzer, the ear and the models.
- `being/ear.mjs`: 28 self-tuned Hopf units (55 Hz–5.9 kHz). It also derives onset, roughness, sub-bass and level.
- `being/tissue.mjs`: a 128×64 Kinouchi excitable sheet with rate homeostasis, rendered as an RGBA texture. Optional STDP plasticity on its links (`plastic`, on in `worker.mjs` at 0.05) and a closed loop after Kagan et al. 2022: the page sends `feedback` to the worker on each heard drum hit while `SHOW.gate` is open, `pattern` (a fixed stamp of cells in the drum's band) when it had predicted the hit, `noise` (as many random cells) when the hit surprised it. Predictable feedback wears the stamp's paths (lab `11-predictive-feedback.mjs`). The mind also takes `senses.predicted` (timing's share of predicted hits) as a small reward.
- `being/kuramoto.mjs` (pure): the motor population. 8 body regions (cube-corner directions, `REGION_DIRS`) × 6 phase oscillators, Lorentzian spread, nonlocal coupling with a phase lag below the critical coupling, forced by drives `{ phase, hz, gain, w }`. `mind.mjs` drives it with the felt pulse (only while onsets keep coming), a cross pulse (the bank's strongest non-octave peak) over the regions around the being's own cross axis, and the beat tracker; `mind.lock` is the strongest of its order parameter over the main regions, the bank's salience while onsets keep coming, and the tracker (rising in ~0.25 s, falling over ~1.2 s, so a messy bar does not drop it), the body's pulse follows its mean phase, and `mind.regions` (`phase` relative to the pulse, `coh`, `cross`) plus `mind.order`/`mind.crossPulse` are exposed. Folded pulses are followed unwrapped so a half-time beat stays the same one. The page's `regionFrame()` swells each region on its own pulse minus the mean (`uRegP[8]`, `uRegA` in `map()`), so it shows only where the body is out of step with itself. Lab: `window.__regions()`, `window.__regionsA`.
- `being/worker.mjs`: runs the ear and tissue at audio rate.
- `being/mind.mjs`: the inner life (startle, resonance + personal tempo, expectation, value and dopamine, affect, boredom, enculturation, serialize/restore). Arousal and valence settle where the music's own perceived arousal/valence puts them (contagion: `senses.musicA`/`musicV` from the brain's `r.av`, eased ~2.5 s, `mind.contagion` = trust in it); loudness only moves it within that range. Without the model a scaled bottom-up estimate stands in. Lab: `window.__affect()`, `scratch/affect-lab.cjs` (WAV -> `scratch/affect/<name>.jsonl/.svg`), `scratch/record-songs.sh <label>` records what plays, one wav per track.
- `being/memory.mjs`: its memory of songs. Each song gets a 48×24 self-organizing map on the skin, starting from the general map (all songs) mixed with its DNA. `paint()` turns a map into colour (the map's own principal axes, around the being's hue), height (cells and U-matrix veins) and recognition glow. The map is never painted on the body (`uSongAmt` stays 0). Each song grows its own form: a morph genome (`being/morph.mjs`, `morphFor()`) chosen after 20 s of listening and stored in `meta.morph`, plus a Lenia species (`being/species-lenia.mjs`, `speciesFor()`, `meta.lenia`) that is the genome's 'living' family. Both are restored at once when the song returns. Growth is seeded where the sound lands on the song's map (`skin.seedAt()` at the map's best-matching unit). Materials: see `being/materials.mjs` below. Each song remembers the material it was loved in (`meta.material`, an index into the 17; `meta.matScore` accumulates per material). Each song's look (palette, dominant texture family, scale, warp, sharpness) comes from `songLook()` over the analyzer's 14 absolute character descriptors, accumulated in `meta.char`. New songs also get a layout seeded by `keyHash(key)`. The memory skin is gated like a cuttlefish's (`SKIN`, `skinFlush()`): it surfaces at recognition, sections, drops, chills and long grooves, then fades to the plain material. Memory pictures are the song's Lenia skin unrolled as a lit metal relief on the GPU (`songPng()`). Dials (`DIALS`, stored in localStorage): rhythm is 0 for its own felt pulse and 1 for phase/tempo lock to the analyzer's beat tracker (`senses.rhythm`, `senses.beat`). Sync is a delay in ms applied to the ear (`worker.mjs` delay line) and to the analyzer.
- `being/memory-store.cjs`: main-process storage, one `<sha1>.json` plus a `.png` per song, and `_general.json`, under `<userData>/being-memory/<seed>/`. Registered by `main.cjs` and by the smoke harness.
- `media/media.cjs` + `windows-media.ps1`: Windows media-session titles (from the old app). `main.cjs` sends `track` events matched to the captured app.
- `being/morph.mjs` (pure) and `being/morph-gl.mjs`: the song's skin. A genome blends generator families (CPPN, a spherical cell mosaic that cleaves 2, 4, 8, ... as it matures, pollen grain, Turing-like band-limited waves, Apollonian lace, strange-attractor density, and the Lenia 'living' family) with symmetry about a song axis. `morph-gl.mjs` bakes it into a 384 px cube map (r height, g edges, b variation) every other frame; the body uses it as displacement in `map()` (`uMorph`, `uMorphA`, `uMorphD`), as cavity AO (height minus mip 4) and as `pat` for the materials. The page's director (`MORPH`, `morphTick()`) lerps from the being's DNA genome (a per-song variant, `mutate()` by the song key) to the song's over 20 s to 2 min of listening and mutates it at sections. The grown form (and the Lenia skin with it) is hidden at rest, so the body is smooth metal most of the time: `MORPH.show` eases it in at moments (`SKIN.expr`: recognition, the song's own skin, a section at most every 25 s, a drop or chills at most every 12 s) and out over a few seconds, and each time it hides, the next surfacing is mutated into a fresh variant. Cavity AO only appears when the form is well surfaced. Attractor densities are computed in `being/morph-worker.mjs`.
- `being/pressure.mjs` (pure) and `being/beads.mjs`: the bead material. The pressure organ reads the broadcast state (arousal over its resting level, anticipation, groove, fatigue) and emits `burst` and `gather` itself (`pressureTick()`); a burst turns the body into beads: the same shape made of ~16k shining metal balls. A GPU pass sphere-traces from outside along each ball's direction with the body's own `map()` (the body fragment shader up to `main()`), so the balls follow the live shape; they are drawn into the body's scene with depth (`sceneRT` has a depth buffer), and the shell is skipped (`uHide`) so the core shines through the gaps. Subdivision spreads as a wave (`uBA`). Right-click "Turn to beads / melt" toggles it. The earlier WebGPU particle-organism swarm is parked in `lab/prototypes/` (not wired).
- Sleep (`SLEEP`): after ~2 s of silence at the ear the being falls asleep over a few seconds: the shell stays whole, every layer and ornament fades, light, reflections and aura trails dim, the living skin stops growing, and it breathes slowly (~0.2 Hz, `SLEEP.bp`), never on the musical pulse. It wakes within ~0.25 s of sound. Pulse-driven visuals scale by the mind's lock.
- Restraint (`REST`, `restApply()`/`restRestore()` in the page): within each kind of layer only one leads at a time (surface: morph skin, Lenia, spikes, turbulence, grain, facets, ripples; appendages: lobes, tendrils, satellites, drops; inner light: nucleus, tissue), the rest are held to the maximalism level M (the other surfaces to zero below M's resting level), which opens only at peaks (drop, chills, arousal and groove climax). Ornaments (rings, sparks, rays, halo, film) live only at M. Computed values are restored each frame before the layers update, so restraint never feeds back into their dynamics.
- Performance notes: when fully asleep (`SLEEP.z > .98`) the page renders every other frame (aura decay compensated; `window.__noHalf` disables) and bakes the skin every 8th frame; the skin's mip chain is generated once per bake, not per face; `ear.mjs` keeps its state in typed arrays and `tissue.mjs` steps only active cells (both bit-identical, `tests/perf-equivalence.test.mjs`); the tissue texture buffer is recycled between worker and page.
- Motion (`danceFrame`, `MOT`, `BOUNCE`): the body dances on the predicted beat (a dip each beat, a sway every two, a swell), as big as it is locked in and grooving; then size, shell, spikes, turbulence, kick and position are eased (quick rise, slow fall), so hits push the dance rather than jolt the body. Rotation jolts are halved and eased (`S.jitS`), glitches need very rough music (`Q.frac > .65`). "Bounce to the beat" (dashboard Actions, `settings.bounce`, page `BOUNCE`; "Calm" in Settings, `settings.calm`, also stills glints and stars) turns the beat pulse, kick jolts, jitter, bass bounce and the dance off. Liquid metal is the home material (what is left when nothing is strongly wanted).
- Voice (`being/voice.mjs` pure, `voice-director.mjs`, `voice-worklet.js`): it keeps sketches of its ear (4 s before, 2 s after) around chills, dopamine peaks and "Love this", a love map over the song map and the song's chroma (`meta.sketches`, `meta.love`, `meta.chroma`); never audio. The sing button (third button in `#fb`, beside love and not-this) toggles singing: hum (28 Hopf emitters) -> babble (vocoded walk over the map on the remembered tempo) -> replay of a kept moment, through a metal-shell modal resonator, a whisper by default (`voice.mode`, dashboard `{k:'voice'}`), at most ~30 s. Its own voice is silenced in what it hears when the captured sound is only its echo (`voice.isOwn`), and it does not learn or keep sketches while singing.
- Hatching (`HATCH`, `hatchFrame`, `hatchSwap`): a new being withdraws the old one into a seed of light (shrink, smooth, glow), swaps seed, mind, DNA skin, species, materials and memory at the darkest point (saving the old being first, under its own seed), then emerges with an overshoot.
- Skin cross-fade (`morph-gl.mjs` `freeze()`): whenever a discrete part of the genome changes (families, symmetry, activations, cell count/layout, attractor, turing seed) or a new attractor image arrives, the current cube map is copied to a snapshot and the bake dissolves from it over ~1.8 s.
- The genre / mood model (`being/ml/brain*.mjs`, `mel.mjs`, Discogs-EffNet ONNX models in `being/models/`, `onnxruntime-web`) runs in a worker and is shown in the dashboard (`snap.brain`); it steers the being (species, taste) only when `ML.brainDrives` is enabled there. The same window also feeds MusiCNN-MSD + the emoMusic and DEAM arousal/valence heads (`r.av`: arousal 0..1, valence -1..1), which the mind always uses.
- The sky (`being/cosmos/`, right-click "Sky", `settings.cosmos` in `being-settings.json`): `sky.mjs` (pure; astronomy-engine, checked against JPL Horizons in `tests/cosmos.test.mjs`) computes ecliptic longitudes and the constellation each body stands in, the rising and culminating points of the ecliptic, the Moon's phase and quarters, temporal hours, the Sun's four stations (sunrise, solar noon, sunset, solar midnight), the last March equinox, and the day's arcs (`dayArcs()`: altitude through the day, rise/transit/set) for `settings.cosmos.place` (default Buenos Aires); `tables.mjs` (pure data: a colour and a metal per body, twelve 30° sectors with a material and a pace each); `rng.mjs` (pure: a randomness monitor, one 200-bit trial per second, chi-square index, uniform under chance); `align.mjs` (pure: enabled modes -> targets for light, metal, stains, material affinity, time flow, core, glow, env, film; flare events). `service.mjs` runs in the main process (sky in `sky-worker.mjs` every 20 s; NOAA SWPC and ANU QRNG polled only while their mode or the sky window is on) and `main.cjs` broadcasts `cosmos` to the page (`COS`, `cosmosFrame()`, `drawSkyRing()`, `stationFrame()` in `being/index.html`) and to the sky window (`being/sky.html`, `sky-preload.cjs`, `--sky`).
- `being/materials.mjs` (pure): 39 materials (the original six; fire, water, air, earth; seven metals named for the bodies they were paired with: lead, tin, iron, gold, copper, quicksilver, silver; twelve stones, 17-28, one per pitch class and per 30° sector of the sky (`SECTOR_ID`); ten gems, 29-38 (`GEM_ID`), each lit when two of its kin (`KIN`) are strong together), each with an affinity (`affinities()` from the mind and the analyzer's character). Soft Lotka-Volterra competition (beta 0.35) plus habituation lets 2-4 coexist and take turns; moments (`MAT.m.moment()`: a section, the drop, chills, a remembered song) speed change. The four strongest go to the shader as slots (`uMid`, `uMw`); `matShade(id, ...)` in `being/index.html` shades each, and the body is marbled into flowing territories (`uMatMix` 0 even blend .. 1 crisp, `uMatScale`), at most four materials per pixel. The new materials also tint the light (`materialLight()`) and lend form after restraint (`matShape()`: fire and iron boil, earth and lead facet, water, air and quicksilver ripple). Air is partly transparent (`matA` alpha). Stones and gems are always shaded by `propShade()`. `lightCast()` gives the light's four casts (`uCast`: radiant core, reflective, sharp, gold flecks). Some materials carry a phenomenon beyond their surface (`PHEN`, `phenFrame()`, `uPhen`): gold's light shafts, tin's vortex in the echoes, silver's caustics, iron's discharge at hits, and each metal's number as cymatics (`uCyN`). Sky modes lean it (`align.mjs`). Lab: `window.__matSlots = { ids, w }`, `scratch/material-gallery.cjs`, `scratch/material-perf.cjs`.
- Proposed materials (on by default, off in the smoke tests, `?test`): `PROP` in `being/index.html` (`?prop=1`, localStorage `on-proposals`, the dashboard's Material panel chip, `window.__proposals(true)`) replaces the shading of the 11 elements and planets with `propShade()` and moves the shell radially with `propShape()` (fire tongues, water chop, earth shells, Mars ridges), weighted by each material's share (`uPWa/b/c`); overlays (stains, thin-shell light, skin, tissue) fade under them. Prototype and review: `lab/prototypes/material-proposals.html`. Harness: `PROP=1 scratch/material-gallery.cjs`.
- Experimental features (`settings.experimental` in `being-settings.json`, `EXPERIMENTAL`/`setExperimental()` in `main.cjs`, dashboard "Experimental" group): the sky (and any the local folder adds) is off by default and switched on separately. While off, the right-click menu has no entry for it, the dashboard hides its panel, and `setCosmos` refuses to start it; switching it off stops it. Existing settings files keep whatever was already in use (migration at load). The sky's mode and ring switches and "Open the sky" live in that group (dash-app `cosmos`). Love / not-this are the hover buttons only, not in the menu. The menu is: Listen to, beads, new form, (experimental entries), Settings, Dashboard, Size, Always on top, window, Quit; Showcase, Bounce, memories and a new being are dashboard Actions. Ctrl+Alt+O (`MENU_KEY`, a global shortcut) opens the menu at the pointer. The source chosen by hand is remembered (`settings.source`, `remember()`) and picked again at launch when that app runs; Settings has "Reset all settings" (relaunches; the window's place, form and memories are kept). The dashboard's tuning, presets and uniforms sit under its "Developer" group; it stops sending snapshots while minimized (`dev-pause`).
- The local folder (`being/local/`, git-ignored, never published; its own `being/local/CLAUDE.md`): when present it adds to the app through plain hooks, and ON without it looks and behaves the same otherwise. Page: `EXT` in `being/index.html` (`being/local/page.mjs` `prepare()` adds uniforms and shader pieces `EXT.shader.decl/screen/bubbles` before the body's material is made; `install()` gets the page's handles and sets `EXT.frame(dt, 0|1)`, `EXT.lead` (how far something other than the music leads: dance, regions, rings and serpents step back), `EXT.glow`, `EXT.spread`, `EXT.ring`, `EXT.cymatics`, `EXT.materials`, `EXT.shed`, `EXT.snap`, `EXT.matSnap`, `EXT.command`); its channels to the main process are `pet.ext.on/send` (`ext:*`). Main: `LOCAL`/`EXTM` in `main.cjs` (`being/local/main.cjs`: `EXPERIMENTAL`, `experimentalDefaults()`, `install()` -> `menuItems`, `dashApp`, `pageLoaded`, `experimentalOff`, `lexReady`, `ready`). Dashboard: `DEXT` (`being/local/dashboard.mjs`: `buildLive`, `look`, `render`, `feed`, `experiments`, `applyExp`). Words: the local lexicon's `PLAIN` fills keys only it uses. Tests: `tests/local.test.mjs` runs `being/local/*.test.mjs`; `scratch/witness.cjs` adds `being/local/witness.cjs`. `scratch/fingerprint.cjs` records every shader the page compiles and its uniforms, to check a refactor leaves what ON draws unchanged.
- Sounds of the world and voices (`being/ml/brain-core.mjs` `_events`, YAMNet `audioset-yamnet-1`, front end `ml/vggish-mel.mjs`): `r.events` groups (water, earth, air, fire, storm; speech, singing, choir, rap, chant, whisper, shout, laugh, cry; music). The page eases them (`SND`, `VOX`): world sounds lean the elements; `voiceOrgan()` makes the nucleus the voice (singing opens the skin and rings cymatics at the sung pitch and leaves a trail of light, `particles.trace()`; speech with no music: listening posture, no dance). Lab: `window.__vox()`.
- The skin's fractal family (genome `lace`): 15 kinds (`FRACTAL_KINDS`, `fractalFor()` in `morph.mjs`, `fractalHemi()` in `morph-gl.mjs`); sections can switch kind. Lab: `window.__fractal(k)`, `scratch/fractal-gallery.cjs`. A song's history of elements (`meta.matTime`) imprints into its skin (`morph.setImprint()`, morph-gl `imprint()`; lab `window.__imprint`).
- Serpents take journeys (`journeyPoints()` in `flourish.mjs`): out of the nucleus, round the outside, back in, 3-5 s a pass, a new route each pass. Each pass is a phase oscillator: given the felt bar (`c.bars`, `c.perBar` from the page) it is pulled to last 1, 2 or 4 bars and to dive back into the nucleus on the one, and a twin is pulled onto its leader and follows its route; `window.__serpBar = false` lets them roam free. Their capsules are joined with a hard `min` (they share ends and radii, so they meet seamlessly; a smooth union would swell every joint into a bead).
- The body has a nucleus and a radius, no up or down: forces, flows and particles are radial or orbital (`being/particles.mjs`: streaked, cooling embers outward, bubbles from inside popping at the skin, dust falling inward and settling, wind circling).

## Conventions

- `being/ear.mjs`, `tissue.mjs`, `mind.mjs`, `kuramoto.mjs`, `timing.mjs`, `morph.mjs`, `pressure.mjs`, `voice.mjs`, `restraint.mjs`, `physics.mjs` and `fft.mjs` stay pure (no DOM), so `node --test` can run them.
- Lab hooks in the page (guarded, inert by default): `__timingInfo`, `__morph`, `__morphForce`, `__morphBench`, `__beads`, `__beadInfo`, `__rest`, `__gpuT`/`__gpuStats` (GPU timer queries per pass). Harnesses live in `scratch/` (`latency-lab.cjs`, `morph-gallery.cjs`, `perf-lab.cjs`, `bake-bench.cjs`, `beads-lab.cjs`).
- Every state variable in `mind.mjs` cites the mechanism it implements. The body reads the mind's states; the exceptions are reflexes, which are direct by design: the core follows the lead and the voice, the shell flinches on kicks, hats raise the spikes, pads the halo (the frame loop in `being/index.html`). Do not add new direct sound-to-shape mappings beyond reflexes. The one deliberate exception is the experimental organism drive (`settings.organism.drive`, `ORGD` in `being/index.html`): while it is on, the lab organism, not the mind, moves the body; it is switchable and exact when off.
- Guard time steps: the frame loop uses its own clock (`beingClock`), and `mind.step` clamps `dt` and resets non-finite state. THREE.Timer returns 0 or negative steps.
- Changes to `being/index.html` are made by small, reviewable edits to the copied entity code. Keep the original structure recognisable.
- Lab hooks: `window.__being()` returns live state and `window.__force = { uniform: value }` pins uniforms.
